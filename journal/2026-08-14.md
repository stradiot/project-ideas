## homepage

Added a link to the project-ideas GitHub Pages site (stradiot.github.io/project-ideas) from the homepage's Engineering & Local section.

The homepage is a single `index.html` with no build step, so the whole site is one file to reason about. Its link data lives in an inline JSON island — a `<script type="application/json" id="config">` block — parsed once at load with `JSON.parse` into a `CONFIG` object that the page walks to build each category's cards. That parser is strict in a way a plain JS object literal would not be: no trailing commas, no comments, no partial recovery. One stray comma throws inside the parse and the whole grid renders empty while the CSS still looks fine, so nothing on screen hints at where the problem is. That is a property of `JSON.parse` versus a JS literal, not something specific to this page, and it is why the edit got checked with an actual parser before being committed rather than eyeballed in the diff.

Icons are not a field on the link entry — they are looked up by the link's `id` through a `getIcon(id, size)` helper that does `ICONS[id] || ICONS.default`, falling back silently to a generic placeholder glyph when the id has no match. A typo in the id is therefore invisible unless checked deliberately; it does not error, it just renders the wrong icon. The same `id` also keys a frecency counter in local storage, which is what decides display order within a section, so the id has to stay unique across the whole page, not just within its category.

Adding the link meant a new entry in the JSON island plus a matching `ICONS` entry, since a plain lightbulb was already taken by the Keep card in a different section — reusing it two sections apart would have read as a duplicate glyph. Drew a rayed-bulb instead, in the same stroke-only 24×24 style as the rest of the icon set, and picked amber for the card colour since Engineering & Local already used purple, cyan and blue and amber was free there. The icon coordinates as first drafted put two ray endpoints (`y2="0.5"`, `x2="3"`) outside the 24×24 SVG viewBox, which would have clipped them at render; caught by re-checking the numbers against the viewBox bounds rather than trusting the sketch, and corrected to sit inside it.

Verification for both edits used strict parsers rather than reading the diff: the JSON island parsed clean with 18 links, no duplicate ids, and every link now resolving to a real `ICONS` entry instead of the generic fallback; the new SVG parsed as well-formed XML with all primitives inside the viewBox. What did not get checked is the actual render — no way to open a browser this session, so the amber bulb next to the JLCPCB card, and the page not coming up blank, is unconfirmed. Committed as `61bf20f` directly to main. The new card starts at frecency zero, so it will sit at the bottom of its section until clicked a few times — next step is opening the page to confirm it renders as expected.
